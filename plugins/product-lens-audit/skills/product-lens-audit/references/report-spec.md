# Report specification

The report is one self-contained HTML page. `assets/report-template.html` implements everything below and renders it from one `<script type="application/json" id="audit">` block; you write only that JSON (`audit.schema.json`, example in `assets/example-audit.json`). Rebuild from this spec only if the template cannot be used.

## Look

Annual-report style: white ground, black ink, one vermilion accent (#ff4a1c) only for the constraint and the top 3 bets, amber for warnings; dark theme on #120d0b (the page follows `prefers-color-scheme` and a `data-theme` attribute on the root). Titles in Sofia Sans Condensed 800, text in Sofia Sans (both cover Latin and Cyrillic). Simple stroke SVG icons per lens, no emoji. It must work at 360px: tables become stacked cards, the journey route turns vertical. Every derived number (ICE, health index, quick wins, confidence, step conversion) is computed by the template, never typed.

Headings state their point ("The journey breaks between teams"), not a topic ("Customer journey"). If any data is sample or assumed, say so once in a small label at the top. Footer: generated by product-lens-audit.

## Sections, in order

1. **Header** - headline = the main finding (usually the constraint, with its number); one-sentence lead; KPI row: lens health index (average of lens scores), the constraint metric vs target, one more key number, number of quick wins. Then the journey funnel as horizontal bars of step-to-step conversion, the constraint bar in vermilion with a short note. Under it, the product stage strip (5 Lean Analytics stages, the current one filled) with one sentence on what blocks the next stage.
2. **Lenses** - radar chart of all 13 lens scores (0-100, low = untapped potential) beside a grouped list with meters (5 groups: improve, right problem, grow differently, change the game, protect value).
3. **Journey** - service-blueprint route of 6-8 stops: owner, stage, one-line pain, status ok / friction / blocking.
4. **Impact-effort matrix** - numbered dots per opportunity; filled = optimize, outlined vermilion = explore; quick-wins quadrant tinted; heading states how many quick wins. Give no two opportunities the same (effort, impact) point.
5. **Opportunities table** - sorted by ICE, filter chips (all / optimize / explore), columns: #, opportunity (with an observed/hypothesis badge), lens (icon + name), type, I, C, E, ICE with bar; top 3 highlighted.
6. **Next 3 actions** - cards with hypothesis ("If we X, then Y improves, because Z"), success metric, cheapest test.
7. **Full plan for every opportunity** - one collapsible row per opportunity, sorted by ICE, top 3 open, plus an "expand all" button. Summary line: number, title, lens, ICE, type, effort, observed/hypothesis badge. Body: **Why it is here** (the evidence: numbers, pages, owner's words), **What to do** (3-5 concrete numbered steps naming the real tools and settings the product uses), **Metric**, **Effort** (hours/days), **Risk / guardrail**. Top 3 also show: alternatives considered, experiment (risk type, success threshold), pre-mortem, and 2 copy variants when the change is about wording. Steps must be specific to this product, not generic advice. Keep this data in one `detail` object keyed by opportunity id.
8. **Data and confidence** - the source list with statuses, a confidence meter (ok = 1, demo = 0.6, no = 0, averaged), what to connect next, the start questions with their answers; a collapsible glossary of all terms; a collapsible "how this report was made".

## Data shapes and language

The full shape is in `audit.schema.json`; `scripts/validate_audit.py` checks it plus the skill's rules. The parts that are easy to get wrong:

- `lang` (`uk` or `en`) picks the interface labels from the template's `UI` dictionary (navigation, filters, table heads, plan labels, matrix quadrants, stage names, lens groups). For another language, add an entry with the same keys.
- `text` holds the report's own words: `label` (small note at the top, e.g. "sample data"), `headline`, `lead`, `funnelNote`, a heading `…H` and intro `…P` per section (`lenses`, `journey`, `matrix`, `ops`, `next`, `plan`, `data`), `how` (list of steps), `footer`. Tokens `{health}`, `{qw}` (quick wins), `{n}` (opportunities), `{conf}` are filled in; `[[words]]` turns red. All text is escaped, so HTML shows as text. A missing or empty key removes that element.
- `kpis`: up to 4 `{v, l, hot?, src?}`. A value with a literal number needs `src` = the name of an entry in `sources`.
- `funnel`: `[{l, n, hot?, note?, sub?}]`. The first item is the base and is not drawn. `n: null` = no data: a hatched bar and a dash. Never put a guessed number there.
- `stage`: `{cur, note}`; `cur` 0 Empathy … 4 Scale.
- `ops`: `{t, l, ln, x: "opt"|"ex", ev: "obs"|"hyp", I, C, E}`; ids are 1-based positions. `detail` and `plans` are keyed by that id as a string. Points with the same effort and impact are spread around the spot on the matrix automatically.
- `answers`: `{q, a, skipped?}`; a skipped one states the assumption in `a`.
- `sources`: `{name, note, status: "ok"|"demo"|"no"}`.
- `glossary`: `{term: {g: short gloss, d: definition}}`.

## Leaks vs target (variant of the header picture)

When the problems are not steps of one funnel (search CTR, returning readers, ad deals), use `leaks` instead of `funnel`: `[{l, v, b, t, sub?}]` - `v` of base `b` against a proposed target `t` %. `v: null` shows "no data". Say in `funnelNote` that the target is a suggested benchmark, not an industry standard.

## Tooltips for terms

Every abbreviation, metric and framework name in the report (CTR, ICE, DR, TOC, JTBD, CPA, LTV, GA4, Direct, growth loops, pre-mortem...) is a dotted-underlined button with a tooltip: the term, a 2-4 word gloss, and one or two plain sentences, ideally with this product's own number ("103 clicks of 6,510 impressions = 1.6%").

- Desktop (a hover-capable fine pointer): opens on hover.
- Phones and tablets: opens on tap; a second tap or a tap elsewhere closes it.
- Keyboard focus opens it, Escape closes it; scrolling more than 40px closes it.
- Definitions live in one glossary object `GL`; the script wraps the first occurrence of each term per paragraph or cell, so the text stays clean. No mode-switch buttons.

## Mobile table cells

In the stacked (phone) table each cell is a flex row of label + value, so every cell's content is wrapped in one `<span class="cv">` - after terms are wrapped, and again after every filter re-render. Without it each text piece and tooltip button becomes its own column and the text breaks apart. On phones the I, C, E columns are hidden and shown inside the ICE cell ("576 = 8x8x9"). After a filter re-renders the table, wrap terms again so tooltips keep working.

## Robustness

- Charts are drawn at real pixel size with a ResizeObserver; bars and meters are HTML rows with a % width.
- All script sits in one block at the end of `<body>`, wrapped in `{ }`, so one error cannot leak globals; check it with `node --check` before delivery.
- `localStorage` is not needed; do not depend on it.
